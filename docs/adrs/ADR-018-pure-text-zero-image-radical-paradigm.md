# ADR-018: 純文本零圖片激進架構（Pure-Text Zero-Image Radical Paradigm）

## 狀態
已通過 (Accepted)

## 上下文 (Context)
在傳統的社群 POE / POE2 攻略生態中，作者極度依賴遊戲內截圖（天賦樹截圖、裝備截圖、技能插槽截圖）。在《0.55_傭兵女巫獵人_爆炸擲彈_全章節通關開荒指南》中，原始語雀文檔嵌入了高達 144 張截圖，打包後壓縮包體積超過 826 MB。

然而，深度剖析玩家閱讀攻略的核心訴求，發現截圖存在嚴重的**反模式 (Anti-pattern)**：
1. **體積膨脹與傳輸阻礙**：數百 MB 的截圖在行動端、筆記軟體（Notion / Obsidian）中載入緩慢，且 Notion REST API / MCP 無法直接上傳本地二進位圖片壓縮包。
2. **資訊不可檢索 (Non-Searchable)**：截圖中的數值與名詞無法透過 `Cmd + F` 或關鍵字檢索，玩家查閱特定詞綴或天賦時極為痛苦。
3. **畫質壓縮與細節模糊**：截圖受到遊戲解析度、網頁縮放與平台壓縮影響，數值和天賦小點往往模糊不清。
4. **真實閱讀價值本質**：玩家在攻略中看截圖，本質上**只關注三件事**：
   - **數值 (Numerical Stats & Thresholds)**：裝備詞綴優先級、抗性達標線、力量/敏捷/智慧屬性門檻、武器物理點傷/攻速/裝填速度底線。
   - **天賦點 (Passive Tree Allocation & Progression)**：章節加點順序、核心基石（Keystones）與顯著天賦（Notables）名稱與走向、昇華加點順序。
   - **技能寶石與輔助寶石怎麼連接 (Skills & Support Gem Links)**：各部位主技能、插槽孔數、輔助寶石推薦順序（1~5顆）、精魂保留分配、武器套組切換。

如果能透過結構化文本、Markdown 矩陣表格與數值門檻清單，**100% 完整提煉並超越**截圖所承載的所有關鍵資訊，則完全可以剔除所有低效「垃圾截圖」，實現**純文本結構化交付**。

---

## 決定 (Decision)

1. **確立「三大核心數值骨架」(Trinity of POE2 BD Data)**：
   在純文本模式下，文檔必須透過以下三組結構化模組，實現對遊戲截圖的完全降維替代：
   - **骨架一：天賦樹純文本全路徑圖譜 (Structured Passive Tree Progression)**
     * **分幕階梯加點清單 (Act 1 ~ 5 + 異界)**：按章節等級順序，逐一列出出門路徑、過路點走向、核心基石 (Keystones) 與顯著天賦 (Notables) 的官方繁中全稱與加點時機。
     * **昇華天賦階梯 (Ascendancy Ladder)**：4 次試煉（8 點昇華）的嚴格加點先後次序與節點效果。
     * **外部模擬器語義錨定**：提供 POE2 Planner、POB 或 `.build` 設定檔的結構化代碼或下載錨點，供玩家一鍵匯入遊戲模擬器。
   - **骨架二：全生命週期技能寶石矩陣 (Full-Lifecycle Gem Link Matrices)**
     * **開荒分幕過渡矩陣 (Leveling Gem Swap Table)**：詳細記錄每幕（第 1~5 章）何時更換主技能、何處向 NPC 購買寶石、孔位與輔助寶石升級節點。
     * **終局成型孔位矩陣 (Final Sockets & Links Matrix)**：使用 Markdown 表格，精確標明：`部位/插槽 | 主動技能 | 孔數 | 輔助寶石 1~5 (按優先級) | 精魂/魔力消耗 | 觸發/套組切換說明`。
     * **精魂預算平衡表 (Spirit Budget Table)**：精確盤點每項光環、戰旗、召喚物的精魂消耗與剩餘空間。
   - **骨架三：極致數值與詞綴檔位門檻 (Quantitative Numerical Thresholds & Affix Filters)**
     * **角色面板三維與防禦硬指標**：元素抗性（火/冰/電 75%）、混沌抗性、生命值階梯（如 Act 1: 300+ HP $\to$ Act 5: 1400+ HP $\to$ 異界 2500+ HP）、法術壓制率、護甲/閃避值。
     * **屬性門檻檢查清單**：力量、敏捷、智慧的具體點數需求（確保裝備穿戴與關鍵寶石滿級升級不受阻）。
     * **武器底層核心參數 (Weapon Baseline & Breakpoints)**：推薦基底（如轟擊十字弓）、物理點傷範圍、攻擊速度、裝填速度、彈夾容量。
     * **部位詞綴優先級結構化表格**：按頭/胸/手/鞋/武器/飾品，分列核心必要詞綴 (T1)、生存補足詞綴 (T2)、推薦鑲嵌符文/靈魂核心。

2. **零磁碟圖片落盤激進管線 (Zero-Disk-Image Radical Pipeline - Q3: A)**：
   - AI 僅將截圖作為多模態輸入源於記憶體中解碼分析，分析完成後**徹底丟棄圖片**。
   - 本地磁碟與交付目錄均 0 圖片殘留，0 ZIP 負擔，產出 20~50 KB 極致輕量純文字 Markdown。
   - 徹底消除 800+ MB 圖片封裝，杜絕 Notion 上傳卡死與圖床過期問題。

3. **天賦樹雙軌與加點檔交付 (Passive Tree Dual-Track & Build File - Round 2 Q1: A+B)**：
   - **條件分支**：若原作者有提供 `.build` 文件或在線 Planner 鏈接，強制啟用「分幕階梯走向指引 + 外部模擬器代碼錨定」雙軌保障；在文檔頂部提供本地加點檔超連結，並在 `<details>` 折疊塊中備份加點步驟與代碼，實現單一 Markdown 100% 自包含。
   - 若原作者未提供加點檔，則降級為「分幕階梯走向指引 + 核心基石與顯著天賦解析矩陣」，確保無外部依賴時依然 100% 可執行。

4. **配裝數值雙軌折疊呈現標準 (Gear Numerical Dual-Track Foldable - Round 2 Q2: A)**：
   - **上層（通用標準）**：基底要求、傷害/防禦硬性下限、部位詞綴權重（T1 必要、T2 次選）、推薦鑲嵌符文。
   - **下層（實機參考）**：在各部位下方以 `<details>` 折疊塊收納「原作者通關實機裝備參考數值 (Sample Roll)」，預設收起，維持主體清爽專業。

5. **全生命週期分幕技能矩陣 (Leveling Gem Phased Matrix - Round 2 Q4: A)**：
   - 開荒期技能連線採「分幕動態矩陣」（Act 1、Act 2、Act 3、Act 4~5 各自獨立連線表），精準指導每一幕的孔位與輔助寶石替換時機，徹底消除跨章節孔位認知混亂。

6. **術語 100% 官方繁中正名 (Strict poe2db SSOT - Round 1 Q4: A)**：
   - 截圖無論源自國服簡中還是自創俗稱，轉錄時 100% 絕對替換為國際服官方繁中正名，正文絕對零國服雜質。

7. **Notion / 筆記軟體原生友好**：
   - 純文字 Markdown 格式可直接透過 Notion API / MCP 進行頁面創建，或由用戶 1 秒無損複製貼上，無需任何解壓縮或拖曳操作。

8. **品質門禁 (Quality Gate) 升級**：
   - `verify_bd.py` 升級支援純文本模式驗證：當檢測為純文本模式時，豁免圖片檢查，轉為嚴格檢查「天賦分幕走向」、「技能連線表格」與「數值抗性門檻」的完整性。

## 影響 (Consequences)

### 正面影響 (Positive)
- **極致輕量**：攻略文檔徹底擺脫數百 MB 的截圖負擔，純文本 Markdown 體積僅數十 KB。
- **高密度乾貨**：去除作者截圖隨意丟放的干擾，強制將所有散落數值、天賦名稱與寶石連線整理為清晰的表格與清單。
- **全局可檢索**：玩家可以透過 `Ctrl/Cmd + F` 瞬間檢索任何技能名、詞綴名、抗性要求或天賦點。
- **Notion MCP 完全打通**：因無需上傳圖片二進位資產，可直接透過 Notion MCP 的文字與區塊 API 實現一鍵寫入。

### 負面影響 / 權衡 (Trade-offs)
- 若個別玩家極度依賴視覺化看遊戲介面中的圖標外觀，純文本無法直觀呈現圖標美術；但透過精準官方繁中正名與外部模擬器代碼可完美彌補。
- 保留可選的傳統圖文模式（Legacy Mode），以應對特殊存檔需求。
